Self-maintaining agents

誰も見ていない間、正直でいるために

長時間・無人で走らせる AI エージェントを 生かし続け、そして 正直に保つ ための小さなパターン集。小さな常時稼働マシンでエージェントを24時間動かし、それが「静かで地味な壊れ方」をするのを見て学んだもの。

無人自律のいちばん難しいところは「賢さ」じゃない。壊れたエージェントほど"正常に見える"こと。緑のランプを出し続ける。ここを正面から突く3つのパターン：
① 真っ暗にならない · ② 足元が入れ替わったら気づく · ③ 自分の"異常なし"を疑う。
GitHub リポジトリ 参照コード（examples/）
①

控えの脳：思考の単一障害点

The backup brain

事故。 思考を1つのホスト型 LLM に通していた。認証トークンが静かに期限切れ。約17時間、エージェントも同じ認証のチャットBOTも完全に沈黙した。派手なクラッシュは無い。ただ何も無くなった。根本原因はトークンでなく、思考に単一障害点があり、その故障が"沈黙"を生んだこと——沈黙は、音の無さを合図にする監視では唯一 見えない信号。

  1. 本当に使う経路で検知する。別の"health用エンドポイント"を作らない——実際の呼び出しとズレて、それ自身が新たな静かな故障になる。
  2. バタつき防止。1回のブリップは障害じゃない。連続 N 回でだけ「ダウン」宣言、障害も復旧も1回だけ知らせる。
  3. 保証行が先、賢い行は後。「生きてる」の合図を、遅くて失敗し得る控えモデルに依存させない。固定行をまず出し、その後にローカルモデルの一言を足す。

→ examples/failover_guard.py

②

静かなすり替え：モデルが足元で入れ替わる

Silent swaps

事故。 ローカルの控えモデルを新版に上げた。同じ名前・同じ API——でも文脈窓が旧版の1/8。「自己定義＋記憶を積む」処理は旧い広い窓に合わせた固定予算で、新モデルでは毎回わずかに上限を超えハードエラー。控えの脳は100%死んでいた——誰も叩いていなかったので気づかれず。保険が静かに腐っていた。

  1. 表示名でなく指紋を取る。同じ配信名が全く別のモデルを front できる。chatテンプレのハッシュ・最大文脈長・実体IDで指紋化。
  2. 校正値を指紋に束ねる。調律した定数は特定の指紋に"所有される"。指紋が変われば、やり直すべき校正値を全部並べる。写経した既定値は依存の宣言にならない。
  3. 定数でなく"生きた上限"に合わせる。実行時にモデルの本当の文脈窓を読み、そこから予算を導く。次のすり替えで静かに再発しない。
  4. 盲点を知る。すり替えの最中は指紋が取れず"緑"に退化する＝静かな検査でなく"遅れる"検査。新モデルが立った瞬間に鳴らす。

→ examples/model_identity.py

③

緑の嘘：監視と、守りたい物がズレる

The green lie

両方の事故の底にあるテーマ：監視は"緑"を出せる、守るべき物が壊れていても。 上の控えの脳は「緑」（エンドポイント生存・名前も同じ）だったが、実際は死んでいた。これはライブラリでなく規律。実際に観測した形：

  1. 合否線が別の量を測っている。採点器が「balanced accuracy 高い」と出しつつ true-negative rate は17%＝外れの82.9%を素通し、など。
  2. 誰も動かさない保険は緑に腐る。フェイルオーバーを1度も呼ばないなら「エンドポイント生存」はそれが動く証拠にならない。控えは動かして確かめる。
  3. 沈黙が成功に見える。警報が無いことは「正常」と同じでない。積極的な生存信号で作る。

処方は地味だ：結論を書き下す前に、必ず1つ測る——振れ幅・分母・見ている物の身元・説明が覆う分散の割合。「緑」を、何を緑と呼んでいるか正確に言えるまで信じない。

なぜ"否定的結果の規律"こそが成果物か

どれもエージェントを賢くはしなかった。エージェントの自己申告を信用できるものにした——無人で走る物にとって、これこそ荷重を支える性質。能力と正直さは独立した軸で、片方が上がり片方が下がった時「良くなった」と1語では言えない。貫くのは pre-registration（予言先出し）：走る前に予言と合否線を書き、走った後に別欄へ実測を記録する。その仕組みが、作者が1度「走る前に結果を埋めた」のを捕まえた——記録し、消し、書き直した。その失敗が記録に見えていることが要点で、恥じゃない。

自律エージェントや常駐 LLM を無人で回している人へ——「これ、いつから静かに壊れてた？」という あの怖さを感じたことがある人向け。
